### Autonomous run

Translated from pstack `playbooks/autonomous-run.md`. Cursor's `/loop` → Paseo heartbeats; `show-me-your-work` → `practices/decision-log.md`. Changed: the gates come from my permissions line, and mid-run discoveries are logged, not fixed. Red CI after the PR opens goes to Babysit, not back to the loop, so Opening a PR never runs twice. pstack's router (`skills/poteto-mode/SKILL.md`), not its `autonomous-run.md`, routes large runs to `figure-it-out` and lists the autopilot playbooks. Not ported: `figure-it-out` and the autopilot playbooks.

**You own the finish condition. Define done, then drive to it without stopping.** I'm away, so every decision goes in the log instead of to me. Your first `TaskCreate` declares the work's playbook (such as `feature`), not `autonomous-run`.

1. Check my prompt for the contract: a goal, a finish condition that can pass or fail, permissions, and an escape hatch. If it names no worktree, create one without asking: run `git fetch origin <base>` for the base that Opening a PR step 2 picks, then `create_workspace` with `isolation: "worktree"`, `mode: "branch-off"`, `branchName: "<type>/<short-slug>"`, `baseBranch` set to that base's remote ref, such as `origin/main`. Either way, use that worktree's `workspaceId` for every agent you launch, and start each of your own commands with `cd "<its cwd>" &&`, because the shell returns to the main checkout after every call. If the finish condition is missing or is a duration ("work for 4 hours"), stop and ask. That's the only question you ask before the run.
2. Start the decision log (`practices/decision-log.md`). The first row records the finish condition.
3. Read the work's own playbook and add its steps to your todo list, copied in verbatim. Then do its opening steps, Bug fix 1–2 (reproduce, root-cause) or Feature 1–3 (scouts, design, checkpoint), and log a row for each. The loop (step 4) and step 9 stand in for the rest of its steps: mark those `skip: covered by Autonomous run step N` rather than redoing them. Except: each loop handover carries Bug fix 3's test seam and logging cleanup, Bug fix 5 still runs, and Bug fix 6 still runs but logs a repeat class as `open` (step 7) instead of starting a Correction. Principle: **Fix Root Causes** (`principles/fix-root-causes.md`).
4. Loop. Each iteration: plan the smallest change the evidence justifies, delegate it to a Paseo `worker` agent (see **Subagents** in the router), and verify it against the finish condition. Have the worker commit it if it moved the condition, with the title and body you write in its handover, or revert it if it didn't. Check the commit with `git log`. A change that "might help" gets reverted, not left in. Log one row per iteration. Principle: **Prove It Works** (`principles/prove-it-works.md`). Principle: **Sequence Verifiable Units** (`principles/sequence-verifiable-units.md`).
5. When you're waiting on CI or another slow event, create a Paseo heartbeat sized to when the result is worth re-checking, and delete it when the wait is over. An agent you launched isn't one of these: wait for it in the foreground (see **Subagents** in the router).
6. Log anything you find outside the finish condition, such as another bug, a flaky test, or a broken skill, as a row with result `open`. Don't fix it in this run. Principle: **Laziness Protocol** (`principles/laziness-protocol.md`).
7. Follow my permissions line. Without it: never merge, and never start a Correction (log it as `open`). Stop and write up why only for an irreversible action, a product decision no experiment can settle, or a real dead end. Principle: **Never Block on the Human** (`principles/never-block-on-the-human.md`).
8. Stop when the finish condition is met. A plateau isn't a stop: pivot the approach and keep going. Never relax the finish condition to declare victory.
9. Run the **Opening a PR** playbook (`playbooks/opening-a-pr.md`). Its step 2 is already done: the worktree's branch is the PR branch. Add its steps to your todo list, copied in verbatim. If the finish condition needs CI green, run the **Babysit** playbook (`playbooks/babysit.md`) in `drive` mode on the PR once it opens, and add its steps to your todo list, copied in verbatim. It fixes red CI and review comments on the PR's branch and never re-runs Opening a PR. Once it reports merge-ready, go on to step 10. A blocker it reports instead of fixing, such as a needed rebase, is a dead end under step 7.
10. Before your reply, check the log and get the trail reviewed, as `practices/decision-log.md` says.

**Reply:** the finish condition and its final state, iterations run, what landed, what was discarded, the `open` rows, and the PR link. End with the **Attention** section.
